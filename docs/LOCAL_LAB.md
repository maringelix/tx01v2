# Local lab

The v1 lab had a complete platform — Istio, Prometheus/Grafana/Alertmanager, Loki,
Argo CD, Gatekeeper, Trivy Operator, backup and Chaos Mesh — but it existed only in
the cloud, and much of it never worked in practice (`docs/LESSONS_LEARNED.md`).
The local lab builds that platform in Docker on your machine, with Terraform,
and checks each part through actual traffic or API calls. Nothing here contacts AWS.

Evidence: the `e2e` CI job checks the complete platform; see Actions for the current
revision. Historical local evidence from 2026-10-14: `observability` (22 probes)
and `operations` (24 probes), each from creation through destruction. The `small`
size below is `verified in CI` by dx01v2 `e2e-platform-small`: the `full` platform
and app, with Docker limited to 7 GB. Historical probe counts below describe those
runs; the scripts and run reports define today's probe set.

v1 stopped at its "next steps" (multi-region DR, FinOps, chaos and OpenTelemetry
observability). Two were already implemented and exercised in the original local
platform: OpenTelemetry traces (Collector, Tempo, Istio Gateway spans, spanmetrics
with exemplars, Grafana links between logs, metrics and traces) and chaos
experiments with hypotheses (pod kill, network latency, CPU and memory stress).
R9/R10 now add local HA, PITR, backup and FinOps exercises; see
[CONTINUITY.md](CONTINUITY.md) and [FINOPS.md](FINOPS.md). Alerts can also reach
Slack, as in v1; the webhook is never committed.

## What is created

`terraform/envs/local` (providers `kreuzwerker/docker` 4.6, `hashicorp/tls` 4.4,
`hashicorp/random` 3.9; local state outside the repository in
`~/.local/state/tx01v2-local`):

| AWS | Local lab | Address |
|---|---|---|
| VPC | Docker network `tx01v2-local` (`10.250.0.0/24`; upper half reserved for nodes and load balancers) | — |
| EKS 1.36 | kind cluster `tx01v2-local` (Kubernetes 1.36, kindnet with NetworkPolicy) | API on 127.0.0.1, random port |
| ECR | Registry (CNCF Distribution 3.1.2) | Push at `localhost:5001`, pull as `registry.tx01v2.local` |
| RDS PostgreSQL 17 with `rds.force_ssl` | PostgreSQL 17, `hostssl` + SCRAM, plaintext rejected, lab-CA certificate | `10.250.0.11`, `db.tx01v2.local` |
| ACM / RDS CA bundle | Lab CA (ECDSA P-256, 30 days), generated by provider `tls` | — |
| S3 | Versity S3 Gateway 1.8.0 (buckets `tx01v2-local-velero`, `tx01v2-local-db-backups`) | `http://10.250.0.12:7070` |
| ALB / NLB (AWS Load Balancer Controller) | cloud-provider-kind 0.12.0: one Envoy per `LoadBalancer` Service | Upper half of the network |
| GitHub (GitOps source) | Soft Serve 0.12.3: SSH push with the state-held key, anonymous HTTP reads | `10.250.0.13` |

All containers and volumes have label `tx01v2.lab=local`. Only the registry
publishes a host port, bound to 127.0.0.1. Credentials (database password, admin
token, S3 keys, Grafana password and SSH key) are generated by Terraform and
stored in local state: they are valid only on this machine and disappear on destroy.

`platform/local/install.sh` installs these layers in order (versions and SHA256
in `platform/local/versions.env`, image digests in `platform/local/values/`):

| Layer | Components | Profile |
|---|---|---|
| core | Gateway API 1.6.3 (experimental retries), Istio 1.31.1 ambient (istiod, istio-cni, ztunnel, GatewayClass `istio` and dx01v2 waypoint), cert-manager 1.21.2 + ClusterIssuer `lab-ca`, External Secrets 2.12.0 + ClusterSecretStore `local-secrets`, metrics-server 0.9.0, contract `lab-system/lab-contract` | All |
| observability | kube-prometheus-stack 92.3.0 (Prometheus 3.15 with exemplars, Alertmanager 0.34 → `alert-sink` and Slack, Grafana 13.2 ClusterIP only, kube-state-metrics, node-exporter), Loki 3.6 (single binary), Alloy 1.20, Tempo 3.1 (single binary), OpenTelemetry Collector 0.162 (OTLP → Tempo + spanmetrics), Istio `Telemetry` (Gateway spans) | `observability`, `full` |
| operations | Argo CD 3.5.5, Gatekeeper 3.23.1 + policies, Trivy Operator 0.35, Velero 1.18 (AWS plugin → emulated S3), Chaos Mesh 2.8.4 | `operations`, `full` |

EKS `full` additionally installs Kyverno to verify ECR promotion attestations and
uses encrypted gp3 PVCs for signals. The local profile does not emulate AWS
credentials or ECR admission runtime; CI renders and schema-checks these
manifests and checks identities with Terraform tests.

Pod Security is `restricted` in all namespaces except `istio-system`,
`monitoring-agents` and `chaos-mesh` (`privileged`: they manipulate node networking
or processes), and `trivy-system` (`baseline`, with `restricted` warnings). App
namespace `dx01v2` is `restricted`, belongs to ambient mesh and has Gatekeeper
constraints in `deny`.

## Running it

Use Linux, WSL 2 or the devcontainer, Docker, and the tools from `make tools`.
The default single-node `full` platform historically needed about 8 GB; `small`
uses 7 GB (below), and `core` fits in 3 GB. Current multi-node HA CI uses
`LOCAL_TOPOLOGY=ha` with **12 GiB Docker recommended**, `LOCAL_SIZE=default`.
HA and `small` cannot be combined.

```bash
make e2e                          # create + probes + destroy (also destroys after failure)
LOCAL_PROFILE=core make local-up  # base only; observability and operations are other profiles
LOCAL_SIZE=small make local-up    # complete single-node platform with less memory (7 GB)
LOCAL_TOPOLOGY=ha make local-up   # multi-node HA topology; default size, 12 GiB recommended
make local-check                  # probes for installed components
make local-down                   # destroy + scripts/leftovers-local.sh
scripts/local-lab.sh status       # lab containers and nodes
export KUBECONFIG="$(scripts/local-lab.sh kubeconfig)"   # kubectl against this lab
```

The lab uses its own kubeconfig (`$LOCAL_STATE_DIR/kubeconfig`); it never reads or
changes the machine's `~/.kube/config`. The `platform/local` scripts reject every
context other than `kind-tx01v2-local`, including standalone calls, because
`uninstall.sh` deletes all Gateways and `LoadBalancer` Services in its target
cluster (harness `policy-scripts` check).

The devcontainer has its own Docker daemon (Docker-in-Docker), so these commands
work unchanged (`LOCAL_PROFILE=core make e2e` was verified locally on 2026-10-14).
Inside a container using the host Docker socket, export `LOCAL_KIND_INTERNAL=1`:
the script joins the lab network and uses the API's internal address.

Grafana: `kubectl -n monitoring port-forward svc/kube-prometheus-stack-grafana 3000:80`,
user `admin`, password from
`terraform -chdir=terraform/envs/local output -raw grafana_admin_password`
with the `TF_DATA_DIR` used by `scripts/local-lab.sh`. In Explore, the Tempo
datasource opens a trace by ID; "Logs for this span" links to Loki lines with the
same `trace_id`, and Prometheus graph exemplars link to the trace. Argo CD has no
local admin user: inspect its Applications with kubectl.

Slack alerts: create an incoming webhook in your workspace and start with
`LOCAL_SLACK_WEBHOOK_URL=https://hooks.slack.com/services/... make local-up`.
`warning` and `critical` alerts reach the channel; without the variable, the Slack
receiver posts to `alert-sink` (the CI path). kubectl receives the webhook over
stdin into Secret `monitoring/alertmanager-slack`, never through files or logs.

## Sizes (`LOCAL_SIZE`)

`LOCAL_SIZE=small` (default: `default`) installs the same components with less
memory. `helm_install` applies `platform/local/values/small/<chart>.yaml` last,
overriding earlier sizing. Components remain the same (app probes use almost all
of them), and the default already uses one replica of each.

| Chart | `small` size |
|---|---|
| kube-prometheus-stack | Prometheus retention 2 h (default 6 h), 20,000 exemplars (default 100,000), limit 640 MiB; disables kubelet cAdvisor/probes endpoints, apiserver histograms and default rule groups consuming those series (probe targets remain); Grafana disables unified alerting (the lab uses Alertmanager) and startup plugin installation, limit 512 MiB |
| Loki, Tempo, Alloy | Limits 320, 320 and 200 MiB; Tempo retention 1 h (default 6 h) |
| OpenTelemetry Collector | Limit 192 MiB (the chart derives `GOMEMLIMIT` and `memory_limiter` from it) |
| Argo CD | Fewer workers (5 status, 2 operation, one repo-server render at a time; the lab has one Application), limits 320, 256 and 192 MiB |
| Gatekeeper | Audit every 5 minutes (default 1), only types used by constraints (otherwise each cycle lists all cluster resource types through the apiserver), limit 384 MiB |
| Trivy Operator | One scan job at a time, operator limit 320 MiB |
| Velero | Limit 256 MiB |

Go components receive `GOMEMLIMIT` below their container limit (Prometheus 3 and
the Collector chart already derive it) so garbage collection runs before an OOM
kill. The control plane does too: `scripts/local/kind-cluster.sh` adds
`terraform/envs/local/kind-config-small.yaml` to kind configuration
(`GOMEMLIMIT` in apiserver, controller-manager and etcd through kubeadm v1beta4
`extraEnvs`). Run `make local-down` before changing an existing lab's size because
an existing cluster is reused. Check `helm-template-local` also renders each chart
with its size overlay, applies the same rules, and rejects overlays that change
images or name nonexistent charts.

Historical memory measurements for `full` with the dx01v2 app, without swap:

| Size | Docker | Result |
|---|---|---|
| `default` | 7 GB (local, 2026-10-15) | Failed: memory hit its limit about 825,000 times (thrashing), apiserver restarted and controllers entered CrashLoop; no OOM kill |
| `default` | CI runner, 16 GB | Passed (this repo's `e2e` and dx01v2 `e2e-platform` jobs) |
| `small` | 6 GB (CI, Docker-in-Docker, 2026-10-15) | Failed: 14 of 18 probes passed; rollout lost 7 of 376 requests; anonymous memory 4.25 GiB, limit hit 468,000 times, 4 OOM kills (Velero plugin copy) |
| `small` | 7 GB (CI, Docker-in-Docker, 2026-10-15) | Passed: 18 probes in about 14 minutes, anonymous memory 4.4 GiB. In one of four runs across the three pairs, the kernel killed the Velero plugin copy twice during installation (BestEffort init container, restarted by kubelet) |
| `small` | 8 GB (CI, Docker-in-Docker, 2026-10-15) | Passed in the same time, anonymous memory 4.37 GiB |

Bruno chose 7 GB for `small` on 2026-10-15 (R1.8 targeted 6 GB): below the
development Docker Desktop's 7.65 GiB and 1 GB below the former single-node
default recommendation. dx01v2 `e2e-platform-small` repeats the proof on each PR.
The largest consumer is apiserver, above 1 GiB with all platform CRDs even with
`GOMEMLIMIT=768MiB`. Job peak working sets on 2026-10-15: apiserver 1248 MiB,
Argo CD controller 306 MiB, Grafana 299 MiB plus 163 MiB for its two sidecars,
Prometheus 236 MiB, Trivy Operator 208 MiB, etcd 150 MiB, and the two Gatekeeper
Pods together 271 MiB.

Without the app, `observability` and `operations` passed at default size using the
development Docker Desktop's 7.65 GiB on 2026-10-14. These measurements predate the
current multi-node HA probes; use 12 GiB for that topology.

## What the probes establish (`platform/local/check.sh`)

| Area | Probe |
|---|---|
| Database | `verify-full` with the lab CA succeeds; plaintext is rejected; physical backup + WAL restore a known point after deletion, and a corrupt backup is rejected |
| Mesh | An allowed identity reaches the service (mTLS through ztunnel); another identity is rejected by `AuthorizationPolicy`; an out-of-mesh client is rejected by `STRICT` |
| Edge | Gateway `Programmed` with emulated load balancer address; HTTPS verified against the lab CA; external `X-Request-Id` (arbitrary text or UUID) reaches the backend unchanged (as on ALB; `gateway-preserve-request-id` EnvoyFilter); HTTP → 301 |
| ACME | Pebble/challtestsrv perform HTTP-01 on the local Gateway; cert-manager issues a 20-minute test certificate and renews it automatically with new revision and serial |
| WAF | ModSecurity with OWASP CRS 4.30.0 forwards a benign request and blocks SQLi; local NGINX rate limiting returns HTTP 429 during a burst |
| Secrets | An ExternalSecret in `dx01v2` becomes a Secret with the contract's five keys |
| Metrics | `kubectl top nodes` (metrics-server) |
| Observability | kube-state-metrics, node-exporter, apiserver and kubelet targets scraped; synthetic `PrometheusRule` reaches `alert-sink` through Alertmanager and the Slack receiver in Slack message format (with `LOCAL_SLACK_WEBHOOK_URL`: delivered notifications and no failures); probe namespace logs appear in Loki; Grafana healthy and ClusterIP only |
| Traces (OpenTelemetry) | An OTLP/HTTP span sent to the Collector appears in Tempo; Gateway continues an incoming W3C `traceparent`, forwards its own span to the backend and reports it to Tempo; spanmetrics generates Prometheus RED series with a trace-ID exemplar; Grafana reaches Tempo and links logs → traces (Loki derived field) and metrics → traces (exemplars) |
| GitOps | Git-server commit synchronized by Argo CD; second commit reconciled; deleted object recreated (self-heal) |
| Policies | Violating Pods rejected by all five Pod constraints; compliant Pod accepted; NodePort Service rejected |
| Registry and scan | A pushed image is pulled by the node; Trivy Operator (ClientServer mode, embedded Trivy server) generates ConfigAuditReport and VulnerabilityReport |
| Backup | Velero restores namespace objects; the separate PostgreSQL drill verifies real data through `pg_basebackup`, WAL/PITR and `pg_verifybackup` |
| Chaos | Hypotheses: with 2 replicas, killing one Pod keeps at least 38/40 requests successful; adding 100 ms network latency to all Pods (`NetworkChaos`) preserves at least 19/20 successes and raises median latency at least 80 ms; CPU/memory `StressChaos` in each container preserves at least 38/40 successes without restarts and with a CPU peak visible in metrics-server |

Current HA, volume-data restore, secret-recovery and FinOps probes extend this
original matrix. Their hypotheses and bounds are documented in CONTINUITY and
FINOPS and implemented in the current scripts; historical probe counts are not
a fixed acceptance threshold.

## Limits (what the local lab does not establish)

- AWS behavior remains `not run in the cloud (v2)`: IAM, Pod Identity, actual
  ALB/WAF, RDS, quotas and billing. The cloud platform implements both `core` and
  `full`, but local success does not validate their AWS runtime.
- The default topology has one node. Multi-node HA exercises require
  `LOCAL_TOPOLOGY=ha`; local failover cannot establish managed EKS/RDS behavior.
- cloud-provider-kind requires the Docker socket to create Envoy containers:
  use a disposable machine or CI.
- The Trivy Operator mirror and `registry.tx01v2.local` mapping exist only locally.
- Logs, metrics, traces and backups live inside the lab (hour-scale retention)
  and disappear on destroy.
- `small` is checked by the dx01v2 app's CI job. The tx multi-node HA `e2e` job
  uses default size; `LOCAL_SIZE=small make e2e` is not equivalent HA evidence.
- Without `LOCAL_SLACK_WEBHOOK_URL`, CI checks the Slack receiver and message
  format, rather than delivery to a real workspace.
